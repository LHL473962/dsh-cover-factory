# 翻唱工厂 · 产品定位（v0.1）

**一句话**：把"A 的声音唱 B"变成一条本地可续跑的生产线——歌手名 / 好球曲 / 目标曲三样输入进去，桌面出 mp3 加一份带质检数字的报告；不承诺完美，但每一步可查、可重跑。

## 三类目标用户

1. **有素材的翻唱爱好者**：手里攒了某歌手一批无损或录音室歌，想低成本试"如果 TA 唱这首"。不想学 Applio / RVC 的一堆参数，也不想手动混音。
2. **二创 / 短视频作者**：要稳定出片，还要能复现的记录（jobId、步数、质检）。被平台或合作方问"怎么做的"，报告能直接拿出来。
3. **本地优先的小团队 / 工作室**：素材有版权顾虑，不愿传云端；需要断点续跑、失败可查、成品自动落桌面。

## 和同类工具的区别

| 维度 | 翻唱工厂 | 常见做法 |
| --- | --- | --- |
| 交付形态 | **端到端 0→9**：分离→智选→清洗→数据集→训练→换声→混音→质检→导出，一次作业出 mp3 + 报告 | Applio / RVC GUI 通常停在"训好模型 / 换完人声"，混音和质检靠自己 |
| 换声内核 | 训练用 Applio dsh_rvc2，换声用**旧版 RVC infer（rmvpe）**——稳定、依赖少、行为可预期 | 追新架构 / 新 GUI，链路长、版本易崩，出问题难定位 |
| 混音 | **原比例混音**铁律：人声/伴奏都用 stem 原始电平 0dB/0dB，不拉平；260Hz −1.2dB、9k +1.6dB、IR 1.2s 湿 30%、伴奏 2.8k 让位 −1dB、glue 1.3:1、等响 −14 LUFS、limiter −1.5dB | 常见把伴奏压低、人声拉高"听起来清楚"，破坏原曲比例，一响就假 |
| 质检 | **preflight 硬门槛**：立体声 / 时长 / 峰值 + 响度 −13±1.5 LUFS + 断音率 <12 次/分 + 音域覆盖 ≥70%；不合格标红并给建议 | 靠耳朵收货，出片前没有可量化门槛，换个人听结论就变 |
| 素材筛选 | 自动排除对唱（男声帧 >15%）、<60s，现场降权，参考曲按音色聚类 ×6 加权 | 手动挑，容易混入对唱 / 现场，训练完才发现不对 |
| 状态与续跑 | 全本地，job.json 唯一状态源，done 阶段按签名跳过，train 断点续训 | 一次性脚本或云端队列，失败只能从头再来 |

## 不做什么（边界）

- **不内置音源、不代下**：抓取模式默认关闭（autoDownload=false），v0.1 引擎的 fetch 抓取也只写 TODO 并 skipped。版权与平台风控风险由使用者自负。
- **不保证像本人、不保证商用合规**：音色上限由素材决定；成品是演绎作品，发布/商用前自行确认权利。
- **v0.1 明确没有**：批量出多首、复用已有 .pth 换目标曲、shift 的工具入口、和声生成/分离。
- **适合**：有素材、能等 1.5–5 小时、要可复现和质检的人。
- **不适合**：零素材、想 5 分钟出片、要求以假乱真或"一键发片"的人。
